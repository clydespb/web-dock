# CLAUDE.md — правила проекта WEB•DOCK

Лендинг веб-студии WEB•DOCK (https://web-dock.ru). Статический сайт на чистых HTML/CSS/JS:
без сборщиков, без npm, без фреймворков. Файлы из репозитория отдаются сервером как есть.

## Общение и язык

- Отвечать пользователю на русском.
- Весь контент сайта на русском (`lang="ru"`). Тексты продающие, но без воды.
  Тон: премиальный, уверенный, без канцелярита и восклицательных знаков.
- Названия шагов в `.github/workflows/*.yml` тоже пишутся по-русски, как сейчас.

## Структура

```
index.html            — единственная страница сайта (все секции)
404.html              — страница ошибки (свои стили в <style>, абсолютные пути /assets/...)
assets/css/style.css  — точка входа: только @import остальных файлов
assets/css/*.css      — стили по компонентам/секциям
assets/js/*.js        — по одному модулю на эффект, запуск в app.js
assets/img/           — изображения (webp), assets/img/cases/ — скриншоты кейсов
assets/fonts/         — локальные woff2 (Onest, Fira Sans Extra Condensed, Cormorant Garamond)
.htaccess             — HTTPS-редирект, сжатие, кэш, 404, запрет служебных файлов
robots.txt, sitemap.xml
.github/workflows/deploy.yml — деплой на хостинг Джино по SFTP при push в main
```

Секции `index.html` по порядку: `hero` → `#advantages` → `#projects` (кейсы) → `#services` →
`#process` → `#cta` → `footer#contacts`. Якоря используются в шапке, мобильном меню и футере —
при переименовании `id` обновлять все три места.

## Кэш-бастинг (важно)

Все CSS/JS подключаются с `?v=ГГГГММДД` (сейчас `20261113`), в том числе внутри `style.css`
у каждого `@import`, а также в `404.html`. CSS/JS кэшируются браузером на месяц (`.htaccess`).

- При любом изменении CSS или JS обновить версию **везде одной и той же датой** (сегодняшней):
  `index.html`, `404.html`, `assets/css/style.css`.
- Вторая и следующие публикации за один день — с суффиксом (`20261112-2`, `20261112-3`):
  версия обязана отличаться от уже опубликованной, иначе браузеры возьмут старый кэш.
- Удобно: `grep -rl "v=20261113" . | xargs sed -i 's/v=20261113/v=НОВАЯ_ДАТА/g'`.
- При содержательных изменениях обновить `<lastmod>` в `sitemap.xml`.

## HTML

- Отступ 4 пробела. Блоки внутри секций разделяются пустыми строками — сохранять этот стиль.
- Классы по BEM: `block`, `block__element`, `block--modifier` (`case__media`, `button--ghost`).
  Состояния — классы `is-*` (`is-open`, `is-active`, `is-visible`).
- Семантика: `section`/`article`/`nav`/`main`/`footer`; один `h1` (в hero), дальше `h2`/`h3`.
- Доступность обязательна: декоративные элементы и SVG — `aria-hidden="true"`;
  кнопки-иконки — `aria-label`; у `img` — осмысленный `alt`; skip-link не удалять.
- Внешние ссылки: `target="_blank" rel="noopener noreferrer"`.
- Иконки — инлайн SVG со `stroke="currentColor"`/`fill="currentColor"`, без иконочных шрифтов
  и внешних библиотек.
- Изображения: формат webp, `loading="lazy" decoding="async"` для всего, что ниже первого экрана.
- Неразрывные элементы в телефоне/брендах: `&nbsp;`, `&#8209;` (как в футере).
- Мета-теги, Open Graph, JSON-LD (`ProfessionalService`) и счётчик Яндекс.Метрики (id 112266666)
  в `<head>` не удалять. Контакты (email, телефон, Telegram `t.me/clydespb`) при изменении
  править во всех местах: JSON-LD, hero, футер, плавающая кнопка `.tg-float`.

## CSS

- Новый файл стилей подключать только через `@import` в `assets/css/style.css` с `?v=`.
  Порядок импортов важен: `variables` → базовые → компоненты → секции → `responsive` →
  `typography` → `theme` → `details`. Последние три — слои переопределений, идут в конце.
- Цвета, радиусы, тени, контейнер, переходы — через переменные из `variables.css`
  (`--bg`, `--text`, `--accent`, `--radius`, `--transition`…) и `theme.css`
  (`--accent-warm`, `--sheet*`). Не хардкодить новые цвета, если подходящая переменная есть;
  новую переменную добавлять в `:root`.
- Шрифты: только локальные `@font-face` в `fonts.css` с `font-display:swap` и `unicode-range`
  (кириллица и латиница раздельно). Внешние шрифтовые CDN не подключать.
  Заголовочный шрифт переключается атрибутом `<html data-type="engineering|editorial">`
  через переменные `--font-display`, `--display-*`.
- Стиль записи как в проекте: `свойство:значение;` без пробела после двоеточия, 4 пробела.
- Адаптив — desktop-first, `max-width`. Используемые брейкпоинты: 1440, 1200, 992, 768, 576, 480.
  Новых не вводить без необходимости. Общие правила адаптива — в `responsive.css`.
- Ховер-эффекты оборачивать в `@media (hover:hover)`, анимации — учитывать
  `@media (prefers-reduced-motion:reduce)`.
- Анимировать по возможности только `transform` и `opacity`.

## JavaScript

- Ванильный JS, без библиотек и модулей (`<script>` в конце `body`, без `type="module"`).
- Каждый эффект — отдельный файл с функцией `initXxx()`; вызов добавить в `app.js`
  (в `DOMContentLoaded`), а `<script>` — в `index.html` **перед** `app.js` с `?v=`.
  Исключение: `hero.js` — самовызывающаяся функция.
- В начале каждой функции: ранний `return`, если нужных элементов нет на странице
  (скрипты могут выполняться и там, где секции отсутствуют).
- Учитывать `prefers-reduced-motion: reduce` и для курсорных эффектов
  `(hover: hover) and (pointer: fine)`.
- Обработчики `scroll`/`touch` — `{ passive: true }`, обновления позиции — через
  `requestAnimationFrame`, сдвиги — `translate3d`.
- Глобальные имена только вида `initXxx`; остальное держать внутри функций.

## Производительность

- Скорость — часть продающего обещания сайта (Core Web Vitals). Не добавлять тяжёлые
  зависимости, внешние скрипты (кроме Метрики), крупные неоптимизированные изображения.
- Новые изображения — webp, разумного размера; для hero есть отдельная мобильная версия.
- Критичный шрифт предзагружается (`<link rel="preload" ... onest-cyrillic-400 ...>`).

## Деплой

- Push в `main` → GitHub Actions выгружает репозиторий на хостинг Джино (`lftp mirror --reverse`).
  Исключаются `.git*`, `README.md`, `CLAUDE.md`. Всё остальное в корне попадает на сайт —
  не класть в репозиторий черновики, архивы, исходники макетов и секреты.
- `mirror` запущен **без `--delete`**: удалённые/переименованные файлы остаются на сервере.
  При удалении файла предупредить пользователя, что его нужно убрать с хостинга вручную.
- Работать в отдельных ветках; в `main` не пушить без явной просьбы пользователя —
  это сразу публикует сайт.
- Секреты (`FTP_SERVER`, `FTP_USERNAME`, `FTP_PASSWORD`) хранятся только в GitHub Secrets.

## Проверка перед коммитом

Тестов и линтеров нет. Перед коммитом:
1. Открыть сайт локально (`python3 -m http.server` из корня) и проверить изменённую секцию
   на десктопе и на ширине ~375px; убедиться, что в консоли нет ошибок.
2. Проверить, что версия `?v=` обновлена во всех файлах (при правке CSS/JS).
3. Проверить, что все пути к ресурсам существуют (`404.html` использует абсолютные пути).
